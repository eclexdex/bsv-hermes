# Security boundaries

The six defaults and three offline kits remain custody-free and perform no network calls. The separately enabled mainnet group adds a narrowly scoped dedicated-wallet digest-publication workflow. Import and registration perform no custody/provider I/O. Startup alone captures the operator-chosen directory and isolated SDK interpreter; native arguments cannot supply paths, keys, authority, network, session or caps. There is no automatic profile mutation. See [mainnet deployment and recovery](docs/MAINNET.md).

Hermes plugins are trusted local Python, not a sandbox. The native tools accept supplied bytes/digests/projections, not paths. Retained identity library filesystem helpers are **unregistered**, POSIX-oriented historical APIs, not part of the portable native security boundary; do not use them as a general secret-file reader. No private-opening CLI is bundled. Mainnet init/approval CLI commands are operator-only administration, not authenticated human channels or native tools. A model with unrestricted same-UID terminal/file access can bypass this design; isolate the broker and authority before funding. Wallet and authority files are plaintext, owner-only; private backups are the operator's responsibility. All workers must share one ledger, and no automatic reset/refund/retry is safe after custody or ambiguous dispatch.

Unknown fields, wrong types, non-JSON values, cycles and resource excess reject at a shared pre-serialization guard, with stricter per-protocol schemas. Error messages never echo raw content. Native result envelopes are unified; comparison failure is not execution failure. Invalid approvals and advisory deployment results do not grant any authority.

Do not send seeds, keys, credentials, actual private SOUL/persona content or private host config. Host logs/history can retain input arguments, including supplied nonces. Deterministic commitments allow guessing. Batch proofs remain deterministic and may reveal low-entropy leaves by dictionary guesses despite salting the final root; native proof output is opt-in private export. Keep proofs and opening/projections local; publication requires separate consent.

The local installer is explicit-profile, dry-run by default, refuse-overwrite and hash-verified. It checks selected source/target ancestry for symlinks, rejects hardlinked source files, uses exclusive new destinations and verifies readback. It requires a trusted local filesystem and no concurrent same-UID/root mutation of target ancestors; these portable checks are not a hostile-filesystem sandbox or full race-proof Windows containment. Native runtime never calls the installer. Manifest hashes detect drift/corruption, not malicious-author authenticity.

The host smoke blocks socket connects and uses only temporary synthetic homes/config, but is not an OS sandbox. The mainnet smoke uses real SDK signing and loopback HTTP with fresh never-funded keys, not operator funds. Production OS/custody isolation, human identity/authenticated administration, live funding/broadcast, chain proofs, consensus/SPV, general SDK conformance and legal/license clearance are not certified. Report vulnerabilities privately to the operator until an approved maintainer/security channel exists.
